# M3: measuring the front door from street images (2026-10-03)

M3 is our reimplementation of the ELEV-VISION-SAM idea (`docs/01-plan-harris-pilot.md` §5): find
the door bottom in a street image and turn its angle into a height with geometry, instead of asking
a language model. Mapillary images only (Bee Maps is run by the other image session). Every number is
from `eval_m3.py B C` (`m3_eval_output.txt`) or the command named.

## How it works

1. `m3_views.py`: the same seeded random houses and view filters as `mapillary_views.py` (camera
   8–45 m away, line of sight not blocked by another footprint, house in the field of view), but the
   **whole frame** is kept with its camera model: `camera_type`, `camera_parameters`,
   `computed_rotation` (OpenSfM angle-axis, world → camera), `computed_geometry`.
2. `m3_measure.py`, per house and view:
   - render a **level** virtual pinhole view aimed at the house (pitch and roll removed using
     Mapillary's rotation), so each pixel row is an exact elevation angle;
   - Grounding DINO tiny finds "door" and "house" boxes, and SAM 2.1 tiny refines them to masks
     (both Apache-2.0, CPU);
   - keep the best door whose ray, cast from the camera through the footprints (HCAD 2017 + lidar 2018),
     hits the **target** house first; R = distance to that wall;
   - **diff**: door height above the wall-ground line in the image = R·(tan θ_door − tan θ_ground);
     the camera height cancels. FFE = 2018 lidar ground at the wall + that height.
   - **abs** (fallback when no ground line is found): lidar road under the camera + a typical
     camera height (median of other houses' diff views, per pano / perspective) + R·tan θ_door.
3. Geometry checks that use no answer key: R 8–45 m, door score ≥ 0.3, implied camera height
   1.5–13 ft (catches mis-posed frames; one freeway dashcam frame was placed beside a house),
   height above ground −1 to 15 ft.
4. `eval_m3.py`: per house, the median over its kept views; compared with GBM + lidar ground
   trained on a 10% neighbour pool that excludes the image houses; blend weights by 5-fold CV.

## Coverage

| | Cypress Creek (B) | Clear Lake (C) |
|---|---|---|
| Sampled houses | 1,200 | 2,000 |
| With a posed Mapillary view facing the house | 206 (17%) | 138 (7%) |
| Views measured | 376 | 273 |
| Door found on the target house | 110 | 114 |
| Views kept after geometry checks | 31 | 85 |
| **Houses with an M3 measurement** (precision A+B) | **26 (2.2%)** | **57 (2.9%)** |

## Accuracy on the houses M3 measured (MAE, ft)

| Method | B (n 26) | C (n 57) |
|---|---|---|
| Lidar + neighbours (GBM) | **0.36** | **0.47** |
| M3, all views | 1.36 | 2.27 |
| M3 diff only (ground line seen; B n 15, C n 36) | 1.02 | 0.66 |
| M3 abs only (typical camera height) | 1.78 | 2.76 |
| Blend of M3 + lidar/neighbours (CV weights) | 0.34 | 0.65 |

The Gemini reading (other session, `RESULTS.md`) was 1.00 ft (B) and 1.09 ft (C) on its houses. M3's
diff version is better than Gemini in C (0.66), equal in B, and neither beats lidar + neighbours.
No raised house (true door > 3 ft above the ground) ended up with a kept M3 measurement in either area.

## Why it misses

1. **Ground line nearer than the wall.** The house mask's lower edge is usually the lawn, walk or
   porch slab in front of the house, closer than R; projecting it at R puts the ground too low and
   the door too high (B bias +0.88 ft on diff).
2. **Door recessed behind the footprint edge** (porches, eaves in the roofline outline): R is too
   short, which also pushes the door up.
3. **Wrong door.** Night and holiday-light frames (B's worst: +5.6 ft, a lit window); raised houses
   whose front door is up an outside stair, where the detector takes the ground-level enclosure door
   (C's worst: true 12.7 ft above ground, read 2.8 ft). The second case is the FEMA
   lowest-floor vs front-door ambiguity, seen from the image side.
4. **Camera height is not stable** across Mapillary contributors (phones on dashboards, roof pano
   rigs), so the abs fallback is poor (1.8–2.8 ft).
5. **Image age**: C's images from 2021+ (abs-heavy) score 5.3 ft vs 0.84 ft for ≤ 2017 images.

## Verdict

- On these two areas, street images measure the door for only **2–3% of houses**, and on those houses
  lidar + neighbours is still better (0.36 / 0.47 ft vs M3 0.66–1.02 ft at best).
- Image methods are worth more only where lidar + neighbours fails (raised houses, mixed blocks), and
  that is exactly where the imagery is thinnest and the door choice is ambiguous.
- Next step, if image work continues: true distances from the 3DEP **lidar point cloud** (building
  and ground points along each ray) instead of footprint edges and the image ground line, plus a
  door-choice rule for raised houses (top of exterior stairs).

## Reproduce

```
python mapillary_index.py B -95.580 29.950 -95.530 29.990   # and C -95.130 29.530 -95.080 29.570
python m3_views.py B 1200 ; python m3_views.py C 2000        # needs MAPILLARY_ACCESS_TOKEN
python m3_measure.py B ; python m3_measure.py C              # ~13 s per view on 2 CPU threads
python eval_m3.py B C
```
